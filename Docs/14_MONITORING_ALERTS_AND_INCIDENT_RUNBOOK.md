## 1. Monitoring & System Health Telemetry

### 1.1 Core Platform Health Endpoints
* **Platform Vital Statistics (`GET /api/admin/stats`):**
  * `totalUsers`: Active registered tenants.
  * `totalLinks`: Platform-wide links (subdivided into `active`, `disabled`, `expired`).
  * `totalClicks`: Non-bot click count.
  * `botRatio`: Percentage of total traffic generated by automated crawlers.
  * `topDomains`: Destination domain distribution (highlights suspicious targets).

## 3. Incident Standard Operating Procedures (SOP)

### SOP-01: Resolving a P1 Global Redirection Outage
1. **Verify Edge Gateway:** Open terminal and test short link via curl:
   ```bash
   curl -I https://kcstudio-linkpluse.vercel.app/test-code
   ```
2. **Inspect Vercel Serverless Logs:**
   * Open Vercel Dashboard ➔ **Deployments** ➔ Current Active Deployment ➔ **Functions**.
   * Filter logs by status `500` or `502`.
3. **Check Cache & Database Connectivity:**
   * If error reads `ENOTFOUND db.xxx.supabase.co`, verify that `DATABASE_URL` is utilizing the IPv4 pooler (`aws-0-ap-northeast-2.pooler.supabase.com`) on port `6543`.
4. **Trigger Instant Rollback:**
   * If outage followed a new commit, navigate to Vercel Deployments, locate the last healthy build, and click **Promote to Production**.

---

### SOP-02: Resolving a P2 Database Pool Exhaustion (`EMAXCONNSESSION`)
1. **Symptom:** Logs show `FATAL: remaining connection slots are reserved` or `Timeout: connection pool exhausted`.
2. **Root Cause:** Application connecting via direct session mode (port 5432) rather than transaction mode (port 6543).
3. **Remediation Protocol:**
   * Access Supabase Dashboard ➔ **Project Settings** ➔ **Database** ➔ **Connection Pooling**.
   * Ensure Mode is set to **Transaction** (Port 6543).
   * Update Vercel environment variable `DATABASE_URL` to port 6543.
   * Trigger redeployment to drain stale sessions.

---

### SOP-03: Mitigating a P4 Phishing or Malware Link (Emergency Killswitch)
1. **Identify Malicious Link:** Copy the target code (e.g., `phish123`) or malicious domain (e.g., `malware-drop.com`).
2. **Option A: Disable Specific Link via API / Admin Panel:**
   * Open **Admin Panel** ➔ **Links Tab** ➔ Search code `phish123`.
   * Click **Disable** ➔ Enter reason: *"Violates Terms of Service - Phishing"*.
   * *Under the Hood:* Updates database status to `'disabled'`, sets admin reason, and immediately busts LRU cache (`lruCache.delete('phish123')`). All subsequent clicks immediately serve a branded HTTP 410 page displaying the deactivation reason.
3. **Option B: Global Domain Killswitch via Blocklist:**
   * If multiple links point to the same malicious domain, add the domain to the platform blocklist:
     ```bash
     curl -X POST https://kcstudio-linkpluse.vercel.app/api/admin/blocklist \
       -H "Authorization: Bearer <ADMIN_TOKEN>" \
       -H "Content-Type: application/json" \
       -d '{"domain": "malware-drop.com", "reason": "Active phishing campaign"}'
     ```
   * *Result:* Every existing and future link pointing to `malware-drop.com` or any subdomain (`login.malware-drop.com`) is instantly blocked with an HTTP 403 Shield page.
